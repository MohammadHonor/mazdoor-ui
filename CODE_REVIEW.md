# 🧠 Code Review Guidelines

### Code Quality

- [ ] Code is clean and readable.
- [ ] Follows the project's coding standards.
- [ ] Proper naming conventions are used.

### Functionality

- [ ] Code works as intended.
- [ ] Handles edge cases and errors gracefully.
- [ ] No hardcoded values or magic numbers.

### Testing

- [ ] Tests are written for new features.
- [ ] All tests pass (unit/integration).
- [ ] No broken or skipped tests.

### Security

- [ ] Input is validated and sanitized.
- [ ] No sensitive data is exposed.
- [ ] No insecure dependencies or patterns.

### Performance

- [ ] Code is optimized where necessary.
- [ ] No obvious performance bottlenecks.

## 🛠 How to Review Code

1. Checkout the branch locally.
2. Run the application and test features.
3. Read through the code changes.
4. Use comments for feedback (positive or suggestions).
5. Approve or request changes clearly.

## 📝 Tips for Reviewers

- Be respectful and constructive.
- Ask questions rather than making demands.
- Focus on the code, not the coder.

## 🧪 Tips for Authors

- Keep PRs small and focused.
- Write clear commit messages.
- Add screenshots for UI changes.
- Link related issues/tickets.
